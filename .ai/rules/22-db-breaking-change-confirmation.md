# P0-DB-BREAKING-CHANGE-CONFIRMATION

Priority: P0
Scope: 所有会修改数据库结构或数据的操作（schema、migration、回填脚本、初始化脚本）

## Rule
- 非兼容性数据库变更必须先暂停执行并请求用户二次确认。
- 二次确认时必须说明风险点，至少包含：数据丢失风险、锁表或性能影响、上下游兼容性影响、回滚复杂度。
- 未获得用户明确确认前，不得执行任何会落库的变更命令（包括 migration 执行、`db:push`、回填脚本）。

## Non-Goals
- 不阻断低风险、兼容性变更的正常推进。
- 不要求对只读查询改动进行二次确认。

## Exceptions
- 无。

## Checks
- 相关回复或 PR 描述必须包含风险点与缓解措施。
- 相关变更必须记录确认结论（确认人、确认范围）。
- 缺少确认记录时，拦截执行与合并。
