# P1-FUNCTION-PARAM-DEFAULTS

Priority: P1
Scope: `src/**`, `scripts/**`

## Rule
- 凡是“参数缺失时取默认值”的场景，必须优先写在函数参数定义处，不在函数体内做同层默认值回填。
- 推荐写法：`fn({ a = 1, mode = 'standalone' }: Options = {})`。
- 无论参数结构复杂度如何（含深层解构），都优先在参数定义处通过解构默认值完成缺省。
- 即使存在分支逻辑，也应先在参数位完成缺省，函数体只处理派生计算、校验与流程控制。
- 参数位默认值只对 `undefined` 生效；若需要把 `null` 也视为“未传入”，必须在函数体内显式归一化（如 `x ?? defaultX`）。
- 统一语义：不传或传 `undefined` 表示“使用默认值”；传 `null` 表示“明确使用 null 值”，不得被默认值覆盖。
- 调用侧推荐“不传”而不是显式传 `undefined`；仅在需要占位时才传 `undefined`。
- 默认值来源保持单一：参数缺失默认值放参数位，避免“参数位 + 函数体回填”双路径并存。
- 深层示例：
```ts
function fn(
  {
    a = 1,
    b: {
      c = 2,
      d: {
        e = 3,
        f: { g = 4 } = {},
      } = {},
    } = {},
    h: [i = 5, { j = 6, k: [l = 7] = [] } = {}] = [],
    m: {
      n: [o = 8] = [],
      p: { q = 9 } = {},
    } = {},
    ...rest
  }: any = {
    b: { d: { f: {} } },
    h: [{}, {}],
    m: { n: [] },
  },
) {
  console.log(a, c, e, g, i, j, l, o, q, rest)
}
```

## Non-Goals
- 不限制函数体内的业务分支、派生计算与校验逻辑。
- 不禁止在函数体中显式处理 `null` 语义或三方入参兼容。

## Exceptions
- 框架或三方接口签名受限、无法安全改为参数位解构默认值时，可保留原写法，但需在实现附近注明原因。

## Checks
- 抽查“参数缺失默认值”场景，检查是否直接写在参数定义处。
- 抽查深层参数结构场景，检查是否优先使用参数位解构默认值而非函数体回填。
- 检查是否存在函数体内对同层参数再次回填默认值的写法（如 `x ?? defaultX` 仅用于缺失语义时）。
- 检查是否明确区分 `undefined` 与 `null` 的语义处理（不传/`undefined` 走默认，`null` 保留为显式值）。
