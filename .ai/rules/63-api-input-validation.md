# P1-API-INPUT-VALIDATION

Priority: P1
Scope: `packages/server/src/**`, `packages/server/scripts/**`

## Rule
- 以类型系统为主：已被 TypeScript 类型系统可靠覆盖并通过编译校验的路径，不再增加重复运行时校验。
- 避免“双重校验”带来的维护成本：同一字段语义只保留一处校验来源（优先类型定义与契约定义）。
- 在同一进程内流转的已类型化数据（DTO、service 返回值、插件上下文）默认视为可信，不再二次运行时校验。
- HTTP 输入中的未知字段默认忽略，不因未知字段报错。

## Non-Goals
- 不强制移除所有历史运行时校验代码。
- 不限制业务层对领域规则的必要判断（例如权限、状态机、配额）。

## Exceptions
- 外部不可信边界（HTTP 原始输入、第三方回调、消息队列原始消息）允许在入口做一次运行时校验或解析。
- 安全高风险场景（鉴权、签名、金额、幂等键）允许保留必要的运行时防御检查。
- 已显式声明白名单约束的治理能力（如列表查询白名单）可以拒绝未声明字段。

## Checks
- 新增逻辑若同时存在“类型已覆盖 + 等价运行时重复校验”，应删去重复校验并保留单一来源。
- 入口已完成解析/校验后，service 与 repository 层不得继续做同构字段校验。
- PR 描述需说明：哪些校验由类型系统承担，哪些校验仍属于边界或安全例外。
- 新增入参 schema 时，确认未知字段策略为“忽略”而非“默认拒绝”。
